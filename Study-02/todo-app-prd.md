## 1. 개요

### 1.1 배경
매일 10~20개 정도의 할 일을 관리하는 개인용 웹 애플리케이션이 필요하다. 별도의 설치나 로그인 없이 브라우저에서 바로 실행할 수 있어야 하며, 새로고침해도 입력한 데이터가 유지되어야 한다. 별도 서버나 백엔드 없이 순수 자바스크립트(Vanilla JS)만으로 구현하여 기술적 복잡도를 최소화한다.

### 1.2 목표
- 하루 단위로 할 일을 빠르게 등록하고 관리할 수 있는 가볍고 직관적인 도구를 만든다.
- 업무 / 개인 / 공부 세 가지 카테고리로 할 일을 분류해 한눈에 파악할 수 있게 한다.
- 완료율(진행률)을 시각적으로 보여줘 하루의 성취를 확인할 수 있게 한다.
- 설치, 로그인, 서버 없이 브라우저만으로 동작하고, 데이터는 로컬에 안전하게 보존한다.

### 1.3 비목표 (Out of Scope, v1 기준)
- 다중 기기 간 동기화 (클라우드 백업/로그인)
- 협업 기능 (공유, 초대, 댓글)
- 반복 일정, 알림/리마인더
- 서브태스크, 마감일 외의 세부 일정 관리
- 모바일 네이티브 앱

## 2. 타깃 사용자

- 하루에 10~20개 내외의 할 일을 개인적으로 관리하는 1인 사용자 (Judy 본인)
- 복잡한 프로젝트 관리 도구보다 가볍고 빠른 체크리스트형 도구를 선호
- 별도 회원가입이나 설치 없이 즉시 사용 가능한 도구를 원함

## 3. 사용자 스토리

1. 사용자로서, 새로운 할 일을 빠르게 추가하고 싶다. 그래야 생각났을 때 바로 기록할 수 있다.
2. 사용자로서, 등록한 할 일의 내용을 수정하고 싶다. 그래야 계획이 바뀌어도 유지보수할 수 있다.
3. 사용자로서, 더 이상 필요 없는 할 일을 삭제하고 싶다. 그래야 목록을 깔끔하게 유지할 수 있다.
4. 사용자로서, 할 일을 완료로 체크하고 싶다. 그래야 무엇을 끝냈는지 알 수 있다.
5. 사용자로서, 할 일을 업무/개인/공부로 분류하고 싶다. 그래야 영역별로 할 일을 구분해서 볼 수 있다.
6. 사용자로서, 오늘 얼마나 진행했는지 진행률을 보고 싶다. 그래야 하루의 성취도를 파악할 수 있다.
7. 사용자로서, 브라우저를 새로고침하거나 껐다 켜도 입력한 할 일이 사라지지 않았으면 한다. 그래야 매번 다시 입력하지 않아도 된다.

## 4. 기능 요구사항

### 4.1 할 일 추가
- 입력창에 할 일 내용을 입력하고 등록 버튼(또는 Enter 키)으로 추가한다.
- 추가 시 카테고리(업무/개인/공부)를 함께 지정한다. 기본값은 "개인"으로 한다.
- 빈 내용은 등록되지 않도록 간단한 유효성 검사를 한다.
- 새로 추가된 항목은 목록 상단 또는 하단에 표시한다(정렬 방식은 4.7 참고).

### 4.2 할 일 수정
- 목록에서 항목을 클릭하거나 수정 아이콘을 눌러 내용을 편집할 수 있다.
- 내용 텍스트와 카테고리를 모두 수정할 수 있다.
- 수정 중 취소가 가능해야 한다(변경 사항 미저장 시 원래 값 유지).

### 4.3 할 일 삭제
- 항목별 삭제 버튼(아이콘)을 눌러 개별 삭제한다.
- 실수로 삭제하는 것을 방지하기 위해 간단한 확인(예: 삭제 아이콘 재클릭 확인, 또는 확인창)을 둔다.
- (선택) 완료된 항목 일괄 삭제 기능.

### 4.4 완료 체크
- 각 항목 앞에 체크박스를 두어 완료/미완료를 토글한다.
- 완료된 항목은 취소선 및 흐린 텍스트 등 시각적으로 구분한다.
- 완료 상태는 진행률 계산에 즉시 반영된다.

### 4.5 카테고리 분류
- 카테고리: 업무 / 개인 / 공부 (3종, v1에서는 고정, 추가/커스텀 카테고리는 비목표)
- 각 항목은 카테고리 라벨(색상 태그 등)로 시각적으로 구분된다.
- 카테고리별 필터링: 전체 / 업무 / 개인 / 공부 탭 또는 드롭다운으로 목록을 필터링할 수 있다.

### 4.6 진행률 보기
- 오늘 등록된 전체 할 일 대비 완료된 항목의 비율을 표시한다. (예: "8/12 완료 · 67%")
- 진행률 바(progress bar) 또는 원형 게이지 형태로 시각화한다.
- 카테고리별 진행률도 함께 표시한다(예: 업무 3/5, 개인 2/4, 공부 3/3).

### 4.7 목록 표시 및 정렬
- 기본 정렬은 등록 순서(최근 추가가 위 또는 아래, 택1)로 하되, 완료 항목은 하단으로 이동시켜 미완료 항목에 집중할 수 있게 한다.
- 카테고리 필터와 조합하여 사용할 수 있다.

### 4.8 데이터 저장 (영속성)
- 브라우저의 `localStorage`를 사용하여 할 일 데이터를 저장한다.
- 할 일 추가/수정/삭제/완료 체크 등 모든 변경 사항은 즉시 `localStorage`에 반영되어, 새로고침 또는 브라우저 재시작 후에도 데이터가 유지된다.
- 브라우저 저장소 특성상 기기/브라우저별로 데이터가 분리되며, 캐시나 저장소를 수동으로 삭제하면 데이터가 사라질 수 있음을 사용자가 인지해야 한다(별도 안내 문구 등 고려).

## 5. 데이터 모델 (예시)

```json
{
  "id": "uuid-or-timestamp",
  "text": "보고서 초안 작성",
  "category": "work", // "work" | "personal" | "study"
  "completed": false,
  "createdAt": "2026-09-09T09:00:00+09:00",
  "updatedAt": "2026-09-09T09:10:00+09:00"
}
```

- 전체 할 일 목록은 배열 형태로 `localStorage`의 단일 키(예: `todos`)에 JSON 문자열로 저장한다.
- 데이터 손상/파싱 실패 시를 대비한 예외 처리(파싱 실패 시 빈 배열로 초기화 등)를 포함한다.

## 6. 화면 구성 (예시 레이아웃)

1. **상단 영역**: 앱 제목, 오늘 날짜, 전체 진행률 표시(바 + 텍스트)
2. **입력 영역**: 할 일 입력창 + 카테고리 선택(라디오 버튼/드롭다운) + 추가 버튼
3. **필터 영역**: 전체 / 업무 / 개인 / 공부 필터 탭
4. **목록 영역**: 체크박스 + 내용 + 카테고리 태그 + 수정/삭제 아이콘으로 구성된 항목 리스트
5. **빈 상태(Empty state)**: 할 일이 없을 때 안내 문구 표시

## 7. 비기능 요구사항

| 항목 | 요구사항 |
|---|---|
| 기술 스택 | HTML, CSS, 순수 자바스크립트(Vanilla JS). 프레임워크/빌드 도구 없음 |
| 실행 환경 | 데스크톱/모바일 브라우저 (Chrome 기준, 최신 브라우저 대응) |
| 데이터 저장 | `localStorage` (서버/DB 없음) |
| 파일 구조 | 단일 HTML 파일 또는 HTML+CSS+JS 소수 파일로 구성, 별도 서버 실행 없이 파일 더블클릭으로도 열람 가능 |
| 성능 | 항목 20개 내외 기준으로 지연 없이 즉시 반응 |
| 반응형 디자인 | 데스크톱/모바일 화면 크기에 자연스럽게 대응 |
| 접근성 | 키보드로 기본 조작(입력, Enter로 추가 등) 가능 |

## 8. 성공 지표 (개인용 도구 기준)

- 새로고침/재접속 후 데이터 유실 0건
- 할 일 추가부터 완료 체크까지 각 동작이 클릭/입력 1~2회 내로 완료
- 하루 사용 흐름(추가 → 체크 → 진행률 확인)이 별도 설명 없이 직관적으로 가능
